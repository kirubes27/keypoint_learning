## P2 findings (non-blocking observations)

1. **This session could not independently recompute the supplied SHA-256 binding values.** The audit sandbox denied every hashing tool (`shasum`, `sha256sum`, `openssl dgst`, `python3 -c` with hashlib, both directly and via a subagent). Compensating verification performed: all reviewed bytes were read at HEAD, which is exactly the reviewed candidate commit with a clean tracked tree; the supplied runtime-manifest content hash matches the committed manifest's self-declared `content_hash_sha256` field; the supplied immutable-v1 file hash matches the identical constant in three independent committed locations (`run_task20_collapse_v2_oracles.py:89-91`, `representation_checkpoint_authorization.py:133-135`, and the semantic lock, line 58). Decisively, every supplied hash is recomputed from actual bytes at run time by both the harness (`_validate_fable_review_authority`, `run_task20_collapse_v2_oracles.py:930-977`) and the authorization gate (`_validate_fable_review_binding`, `representation_checkpoint_authorization.py:623-697`), each of which fails closed on any mismatch — so a wrong supplied hash can only block the run, never falsely authorize one.
2. **Duplicated matrix-hash constant.** `TASK20_V2_INDEPENDENT_OUTCOME_MATRIX_SHA256` (`representation_checkpoint_authorization.py:151-153`) restates, as a literal, the canonical hash of the harness's live `INDEPENDENT_OUTCOME_MATRIX`. Consistency between the two is only enforced at authorization time, in the fail-closed direction (a mismatch produces a stuck gate, not a wrong pass).
3. **Tautological execution-commit comparison in suite validation.** In `_validate_committed_task20_v2_planted_suite` (`representation_checkpoint_authorization.py:1178-1201`), the expected `fable_review_authority` block uses `suite.get("execution_commit")` on both sides of the comparison, so the execution commit itself is only format- and ancestry-checked. This binding is weaker than the others but benign: the suite path is keyed by the reviewed candidate commit, the review file hash and reviewed fileset hash are fully pinned, and all reviewed bytes must equal the reviewed-commit blobs.
4. **Operational constraint on retries.** Once suite results are committed, any re-run of the official suite fails the `changed_paths == [review file]` check (`run_task20_collapse_v2_oracles.py:909-921`). This is fail-closed and evidence-preserving (a failed attempt writes nothing, and a fresh `attempt_NNNN` directory works before any new commit), but a post-commit re-run requires a fresh review cycle.
