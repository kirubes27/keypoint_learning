# Independent review — held-out roll fixed-final candidate

**Verdict: PASS_WITH_REQUIRED_FIXES.** The authority chain is real and fail-closed end to end, and the design is right-sized for its purpose. I found one semantic regression in the shared evaluator (P0), one cross-binding gap in the new runtime seam (P1), and a handful of small P2 cleanups. Nothing here undermines the architecture; both required fixes are small.

A process note first: shell access was permission-gated in this session, so I could not recompute the packet SHA-256s. I reviewed the working-tree bytes of the four repo files plus the live `git diff` of the five tracked files, which per the briefing is the same content as the packet. ## P0 — the new cycle predicate silently changes existing full-corpus metrics

- **Where:** `eval_representation.py`, new `_pair_graph_is_one_complete_cycle` (diff hunk at old line ~2999) and its use in `evaluate_bundle` replacing `cyclic=bool(bundle["transform"]["cyclic"])`.
- **Violated claim:** the evaluator change is supposed to *only* stop a held-out path from being wrapped as a cycle, without changing the meaning of existing evidence.
- **Failure mode, concrete:** the predicate requires **one** connected cycle covering all evaluated frames. But the frozen `full_primary_roll` diagnostic (`eval_representation.py:2886-2918`) has frames 0..179 with edges `i → (i+3) mod 180`. Since gcd(3, 180) = 3, that pair graph is **three disjoint 60-edge cycles**. The traversal from frame 0 returns to 0 after 60 steps with 120 frames unvisited and returns False. The full orbit *is* temporally cyclic (frame 179 is adjacent to frame 0, which is exactly what the close-run series at `eval_representation.py:938` wraps over), so wrapping was correct before and is now silently disabled — and the new result field labels a genuinely cyclic orbit `evaluation_frame_sequence_cyclic: false`. Longest-close-run values for any re-run of the full-corpus diagnostic will diverge from previously frozen evidence with no error raised. The passing 67 evaluator tests do not disprove this: `_longest_true_run` ignores `cyclic` for all-true or non-boundary-crossing series, so fixtures can easily miss it, and the candidate's own test only covers the single-cycle toy case.
- **Smallest safe correction:** wrap iff `transform["cyclic"] is True` **and** every evaluated frame has in-degree 1 and out-degree 1 in the pair graph (i.e., the graph is a disjoint union of cycles covering the frame set — a permutation). A held-out segment still refuses (its endpoints break the degree condition — the intended fix is preserved), and the stride-coset full orbit wraps again. This is strictly *less* code than the current traversal. Add one regression test with the 180-frame stride-3 shape.

## P1 — the runtime never re-binds `test_manifest` to the approved committed artifact

- **Where:** `representation_fixed_final_runtime.py:648-666` (`finalize_fixed_final_roll`, `test_manifest: Any`) and `_open_test_frames_once` (line 268); `representation_split_adapter.py` `build_index_manifest_adapter_rows` records `pair_index_binding` but compares it to nothing.
- **Violated claim:** "test split … cross-bound rather than merely logged." The provenance `evaluation_pair_artifact` role hashes the *committed* test pair file, but the rows actually evaluated come from a duck-typed argument object. The only binding is the call-site check in `train.py:1285-1291` (resolved-path equality), outside the authorization chain. The dataset binding is transitively pinned (a doctored binding hash fails geometry-registry authorization), but the *row subset* is not: an alternate future caller passing a stale or differently filtered strict test manifest with the same corpus binding would produce an evidence receipt whose committed-artifact hash and evaluated rows disagree.
- **Smallest safe correction:** carry the test pair `file_sha256` (already computed in `validate_run_manifest`) into `FixedFinalRunBinding`, and in the runtime require `Path(manifest.index_path).resolve() == (repo_root / binding.test_pair_repo_relative_path).resolve()` and `manifest.index_sha256` equal to that stored hash before adapting rows.

## P2 — proportionality and coherence items

1. **Dead code:** `_build_fixed_final_test_loader` (`train.py:1033-1072`) has no remaining caller after the diff. Remove it — a leftover second path to a test `DataLoader` is exactly the kind of latent seam this design is trying to eliminate.
2. **Late-failure asymmetry:** the new `ROLE_PATH_PREFIXES` entries require `decision_spec` / `pro_review` / `fable_review` / `user_approval` / `fixed_final_manifest` to be `.json` files under their prefixes, but `_validate_file_record` in the authorization module only checks the prefix. A `.md` decision spec would authorize, train for hours, then die at evaluator provenance validation. Mirror the `.json` requirement in the authorization module.
3. **Asserted rather than derived ledger:** `each_unique_test_image_opened_once: True` etc. are literals. Cheap hardening: derive counts from the `opened` list and assert image/mask relpath uniqueness across frames (`_frame_records` guarantees unique frame_ids, not unique relpaths).
4. **Rerun surface:** the manifest does not pin `--output_dir`, so one approved manifest can yield multiple complete evidence chains in different output directories. Fixed seed plus the determinism policy makes these near-replicas, and single-run-per-directory is enforced (`mkdir(exist_ok=False)`, O_EXCL receipts), but whether one manifest may authorize more than one run is a governance question worth stating explicitly in the decision spec — not a code change I'd make unilaterally.
5. **Minor:** `_repo_evidence_at_commit` uses plain `git show` without the hardened environment of `authorization._git` (consistent with pre-existing split-bundle style, so not a regression); the evaluation-config literal is now duplicated a fourth time (matches `representation_fresh_checkpoint_runtime.py:468-471` and `representation_checkpoint_runtime.py:1002-1005` exactly — repo convention, and the five representation thresholds are literal-pinned inside `evaluate_bundle:3830-3836`, so drift fails closed; acceptable).
6. **Not test theater:** the six candidate tests are narrow, mock internal seams, and one of them (`test_heldout_roll_path_is_not_mislabeled_as_a_cycle`) enshrines the P0 predicate's flawed intent — update it with the fix. But the suite is proportionate; no broad mutation/fuzz expansion is warranted.

## Safeguards I traced end to end and confirm

- **No run without a committed manifest:** `--fixed_final_manifest` without `--indexed_mode fixed-final` raises; fixed-final mode without a manifest raises inside `bind_training_namespace`; and even if a binding were somehow absent, `train.py:1768-1771` raises before any held-out open. The manifest must be committed, byte-identical to HEAD on a clean named branch, content-hashed, schema-exact, and reference committed decision/Pro/Fable/approval records.
- **Cross-binding, not logging:** training args are compared field-by-field against the argparse namespace; object id, dataset basename, binding hash, and both pair-index paths are pinned; the pair indices must be the frozen +6° stride-3 roll stratum, contain the object under its locked role, and (pre-training, from metadata only — no image decode) have disjoint train/test frame endpoints (`_validate_manifest_pair`, `train.py:760-766`).
- **Receipt-before-decode:** `history.json` now lands before the receipt; `write_training_receipt` re-verifies source state and hashes `final_model.pt`/`config.json`/`history.json` with an O_EXCL write; the finalizer cannot open frames without a capability minted from re-validating that receipt, and the one-shot ContextVar plus O_EXCL bundle/result/receipt writes prevent a second evidence-producing open in or across processes.
- **Checkpoint semantics:** hash and `torch.load(weights_only=True)` through the same file descriptor; exact key set; epoch == frozen_epochs; embedded `fixed_final_contract` (run_id, manifest hashes, seed, role) cross-checked; per-tensor shape/dtype/finiteness; model state digest verified unchanged before and after inference.
- **Same-model, same-inference evidence:** points/logits digests from `_infer_once` must match the bundle's arrays, and the evaluator independently recomputes points from the supplied logits and requires agreement (`eval_representation.py:3563-3580`) — so a preprocessing or convention mismatch fails loudly rather than skewing metrics. Normalization matches training (`dataset.py:877`).
- **Evaluator authority:** armed-bundle hash must equal the evaluated bundle's canonical hash; `run_id == case_id`; checkpoint hash chained from receipt → authorization receipt → provenance load receipt; committed provenance files verified against git blobs at `source_commit`; selection authorized, training forbidden; result must be `partition: test` with `scientific_threshold_status: not_defined_by_evaluator`.
- **Split-bundle change preserves frozen meaning:** previously validation required manifest hashes == working tree == generator commit, which broke whenever any generator source (including `representation_split_bundle.py` itself, which this candidate edits) legitimately evolved. Now manifest hashes bind directly to the historical commit blobs — which is what "frozen" actually means — while independent artifact content hashes, the verifier report, optional byte-identical regeneration, and creation-time `verify_commit_contains_generator_sources` (`representation_split_bundle.py:440,910`) all remain. Sound, arguably stronger.
- **Reuse vs. copy-paste:** a new roll object needs only its own registered geometry binding and approved manifest (the hammer test confirms the adapter path); translation/scale/yaw/pitch are structurally refused — the manifest transform is a pinned roll literal, `_open_test_frames_once` requires `transform_family == "roll"`, and the fixed-final provenance profile forbids `fit_from_pairs`.

## Correctly still blocked (scientific, not engineering)

Task55 vs Task80 (manifest picks one of two allowed ids; code chooses nothing), the exact epoch rule (`frozen_epochs` comes only from the manifest), numeric confirmation pass/fail thresholds (absent everywhere; evaluator refuses to decide), and banana/kettle geometry (must be separately registered and evidence-backed; hammer geometry cannot authorize them). The `ENGINEERING_CONTRACT_v1.md` states these boundaries accurately.
